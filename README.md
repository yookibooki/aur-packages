# aur-packages

Four AUR packages, one command. Everything is manual: no workflows, no
cron, no docs tree — you run it.

## Layout

    ./aur                     every command (run bare for help)
    packages/registry.json    what we track: upstream, asset pattern, archs
    packages/<pkg>/PKGBUILD   package source
    packages/<pkg>/.SRCINFO   generated by makepkg, never hand-edited
    scripts/                  what ./aur calls
    AGENTS.md                 instructions for automated runs

## Commands

| command | what it does |
|---|---|
| `./aur status` | packaged version vs upstream latest, per package |
| `./aur bump [pkg ...]` | update: download real artifacts, sha256, regenerate `.SRCINFO`, verify, consistency (default: all active) |
| `./aur check [pkg ...]` | gate only: consistency + per-package verify |
| `./aur publish [pkg ...]` | push the committed tree to the AUR over SSH |
| `./aur add --pkg X --upstream owner/repo [pattern flags]` | scaffold a package; then `./aur bump X` fills it in |
| `./aur remove X` | deactivate and move `packages/X/` to `archive/` |

Routine:

    ./aur status && ./aur bump    # update
    git diff                      # review what changed
    ./aur check                   # gate
    git add -A && git commit      # record
    ./aur publish                 # ship to the AUR

Needs: bash, python3, makepkg, git, an SSH key with write access to
`aur.archlinux.org`, and optionally `GITHUB_TOKEN` (probe rate limit:
60/h without one).

## Rules

- Checksums come from downloaded artifacts — never `SKIP`, never typed.
- A committed `.SRCINFO` must reproduce from its PKGBUILD:
  `cd packages/X && makepkg --printsrcinfo > .SRCINFO`.
- A release tarball re-cut under an unchanged tag is a supply-chain
  compromise: halt, keep the evidence, do not publish.
- Only active entries in `packages/registry.json` are shipped; a
  inactive package's directory must live in `archive/`.
