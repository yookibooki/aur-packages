# Changelog (2026-09-21)

- Root-caused the daily "run failed" red X. Every scheduled Repo Assist
  run died in the `activation` job at "Validate COPILOT_GITHUB_TOKEN
  secret": the pi engine with a bare/unprefixed model compiles to
  `--model github-copilot/<m>`, which requires that secret
  (presence-validated, and format-checked as a real `github_pat_*` fine-
  grained PAT). It was never set; each failure auto-filed an `[aw] Repo
  Assist failed` issue (#6,7,8,15,16,17). The agent has therefore never
  run since the 09-15 cutover; all `issues`-triggered runs succeeded only
  by skipping activation (no `/repo-assist` command matched).
- Discovered the 09-15/16 workflow work (commit 874f23f + an uncommitted
  sandbox-off recompile) was never pushed; origin/main still carried the
  8ba5485 lock. Working tree and local history reconciled and pushed
  together with this run's engine fix.
- Fixed the engine routing in `.github/workflows/repo-assist.md` and
  recompiled `repo-assist.lock.yml` (gh-aw v0.88.7). Engine stays pi on
  b.ai (maintainer's choice): model becomes `openai/qwen3.8-flash`, so
  gh-aw brokers its native OPENAI_API_KEY/CODEX_API_KEY path (no format
  check, injected into the agent step by the compiler) and activation
  validates that instead of COPILOT_GITHUB_TOKEN. The models.json step
  now defines provider `openai` (baseUrl api.b.ai/v1,
  api openai-completions, per-model override). Verified against pi
  0.84.3 provider-composer source: the extension `pi_provider.cjs`
  registers `openai` with apiKey and no `models`, and `applyExtension()`
  passes models.json entries through untouched when the extension gives
  no `models` and no `baseUrl` (OPENAI_BASE_URL unset). So requests go
  to api.b.ai as openai-completions with the OPENAI_API_KEY value as
  bearer. **Consequence: the b.ai key must be set as repo secret
  `OPENAI_API_KEY` (`gh secret set OPENAI_API_KEY`).** `BAI_API_KEY` was
  proven to be a no-op (engine.env secrets appear nowhere in the
  compiled lock except as a literal string in models.json) and is kept
  until the route is proven green, then deletable. Threat detection
  stays off; sandbox stays off (maintainer decisions, reasons corrected
  in-place in the md comments — the old "engine.env reaches pi" rationale
  was false).
